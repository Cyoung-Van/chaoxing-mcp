# 测试与验证

测试的目标是检查解析、采集、缓存与接口的实际行为，并让数据未知、采集失败和部分结果保持可见。自动化测试通过不能证明所有学校、课程或平台入口均已覆盖。

## 本地检查

需要 Node.js 22 或更新版本。在仓库根目录执行：

```sh
npm ci
npm test
npm run check
```

`npm test` 执行仓库中的自动化测试，`npm run check` 执行项目检查脚本。它们使用的合成样例不应包含真实账户、真实课程、浏览器 Cookie 或真实签名链接。实际检查项以当前测试源码与检查脚本为准。

需要验证 CLI 帮助和诊断时，可再执行：

```sh
node src/cli.mjs --help
npm run doctor
```

无浏览器或未登录时，诊断应准确返回不可连接或需要登录的状态；这不等于通过了账户采集验证。

## 测试证据应如何解读

| 证据 | 可以说明 | 不能说明 |
| --- | --- | --- |
| 合成 HTML / JSON 解析测试 | 给定结构、字段与边界条件下的解析行为 | 线上页面仍然使用相同结构 |
| 模拟传输与采集测试 | 调度、错误传播、部分结果和缓存语义 | 真实登录、平台接口或签名生成可用 |
| MCP / CLI 协议测试 | 输入校验、工具调用、JSON 输出或任务状态可用 | 所有数据源已在真实账户中成功读取 |
| 空列表的真实读取 | 当前账户和当前入口返回了可识别的空结果 | 非空任务能够正确解析，或其他入口也为空 |
| 经脱敏记录的非空真实读取 | 记录范围内的平台结构与结果经过核对 | 其他课程、学校、时间点或隐藏入口全部兼容 |

任务引擎的非空任务包、分组及学习计划当前处于**功能契约与合成测试验证**范围。未完成真实非空样本核对前，不将它标注为“真实账户验证通过”。

## 需要保持的行为

以下是测试与人工复核的重点，不是对当前测试数量或覆盖率的声明：

- 课程、班级及任务标识按字符串处理；仅凭同名标题不合并任务。
- 同一稳定标识出现相互矛盾的状态时，保留未知状态及警告。
- 活动或考试结束不自动推断为本人完成；未知状态在待办中可见。
- 已知空列表可以判空；未知页面、异常响应、未知分页必须标记为失败或部分结果。
- 缺失积分、排名、任务点与练习统计保持 `null`，不补零、不从标题提取成绩。
- 日期解析校验日期有效性；显式时区优先，无时区的平台日期采用 `Asia/Shanghai`；仅有日期时不补小时。
- 登录失效、验证码或取消会终止本轮采集，并保留已取得的结果。
- 筛选刷新替换旧快照，并记录课程范围、模块、截断与核对选项。
- `coverage.complete` 的含义限于选定范围与已实现来源，不能扩展为全平台无遗漏。
- 浏览器会话关闭只清理程序拥有的工作页面，保留用户页面和人工验证入口。
- 不执行页面中提取的脚本，不构造未知签名，也不通过考试作答或播放入口补查元数据。

## 人工验证流程

使用本人有权访问的测试账户或课程，并先核对采集范围。不要为了测试创建或提交真实学习任务。

1. 启动 `npm run browser`，在独立浏览器中手动登录。
2. 执行 `npm run doctor`，确认能连接正确的本地浏览器；用 `node src/cli.mjs courses` 实时读取课程目录，选取一门待核对课程。
3. 用 `npm run sync -- --course "示例课程" --max-courses 1 --sections assignments,exams` 做首次小范围刷新，将课程名替换为实际名称。核对结果后，再逐步加入其他模块与课程。
4. 对照网页检查任务身份、状态、截止时间和进度指标，尤其核对“结束”与“本人完成”的区别。
5. 检查快照时间、`scope` 和 `coverage`。若限额截断、某来源失败或分页未知，确认结果仍明确标为部分采集。
6. 使用 `chaoxing_refresh` 发起异步刷新，将返回的 `jobId` 传入同一 MCP 进程的 `chaoxing_job`，轮询至终态，再查询快照；确认启动响应不被当成最终结果。
7. 按明确请求打开一个已有任务入口，确认没有自动开始考试、提交、签到或播放。

验证码和登录失效场景不应通过主动高频请求制造。自然遇到这些场景时，核对是否停止、保留部分结果并留下人工处理入口即可。

对任务引擎进行真实验证时，需要分别核对非空任务包、分组、学习计划、完成状态、截止时间及可读入口；只有任务包空列表成功不能替代这些检查。无法安全读取子任务时，应保留任务包级入口和未知字段。
